# 购买执行层 · 0.4.0

这次交付的是已经接入扩展后台的执行协调器；**当前真实渠道适配器数量为0，不能在大麦自动锁票**。本文件中的接口是实际代码接口，官方页面动作则尚未实现。

## 用户现在能看到什么

重新加载扩展并刷新计划界面，在“真实购票接入状态”点击“检查接入状态”，会显示已验证渠道数量和当前购买任务。没有任务时，停止、恢复和查单按钮禁用。没有适配器时，启动请求直接失败，不会用模拟页面创建购买记录。

未来渠道接通后：选择项目与有序备选 → 解析真实票档 ID → 启动一个购买任务 → 页面更新触发检查 → 准备结算 → 匹配官方待付款订单后通知付款。当前还没有这条真实端到端流程，也没有准点执行调度器。

## 已实现的执行规则

- 同一扩展后台只有一个 `Coordinator`，所有标签页共用 `purchaseLedger`。并发启动仅一个成功，运行 ID 不匹配的旧请求不能修改新任务。
- 已解析计划只保存项目 ID、有序票档 ID、张数、最高总价（分）与起止时间；忽略其他输入字段。不保存账号、Cookie或观演人身份信息。
- 每次 `tick()` 是一次检查，观察结果必须来自绑定标签页、目标项目，且不超过1500毫秒。这个值是拒绝陈旧信息的检查阈值，不是查询频率或响应速度承诺。
- 明确首选售罄才能看备选；登录、已有订单未确认、验证码、排队、结构异常均暂停。
- 选择后重读结算，核对票档、数量、总价、观演人选择是否已确认、页面文档身份和时限。
- 先成功持久化 `SUBMITTING` 与提交 ID，再调用一次 `submitOnce()`。存储失败、停止或结算已过期均不派发点击。
- 读取、提交回执与查单默认15秒超时。超时不会取消服务器已收到的请求，仍须查单；`prepare()`只允许选票，不得提交，暂不强制超时，停止后禁止进入提交阶段。
- 提交回执本身不表示成功。必须由 `reconcile()` 给出关联本次提交的官方订单证据，订单 ID、项目、票档、数量、金额和创建时间匹配，才显示待付款。
- 订单列表为空不是“未形成订单”的充分证据。只有适配器取得本次提交的权威、已终结的售罄拒绝证据，才能返回最终无订单；然后排除该票档并检查备选。
- 后台重启把提交中改成 `UNKNOWN`、准备中/等待中改成 `PAUSED`，不自动重放点击。停止期间到达的真实成功结果仍记为待付款，不能用“已停止”掩盖已经产生的订单。

## 接入真实渠道时必须补齐的接口

在 `adapters.js` 注册随扩展发布的代码，不接收网站消息或远程配置里的可执行脚本。一个适配器可以支持一类页面和多个项目，但不能只改 `supports()` 返回值就宣称支持。

| 接口 | 输入 | 责任 |
|---|---|---|
| `supports(plan)` | 已解析计划 | 同步确认该项目及渠道在适配范围内 |
| `inspect(plan, context)` | 项目、runId、tabId | 读取真实登录状态、已有订单状态和有唯一ID的候选快照 |
| `prepare(action, context)` | 票档、数量、金额 | 仅选择票档和数量、进入结算；绝不能创建订单 |
| `readCheckout(context)` | 绑定任务与标签 | 返回结算信息、文档 ID 和观演人选择已确认标记 |
| `submitOnce(attempt, context)` | 已持久化的提交意图 | 动作前核对当前文档与全部结算字段，只点击一次，不重试；不执行付款 |
| `reconcile(attempt, context)` | 本次提交身份 | 只读官方订单证据，返回匹配订单、最终无订单证明或未知 |

`context` 含 `runId` 和 `tabId`。具体字段参照 `purchase.js` 与 `tests/purchase.test.cjs`，后者仅是测试替身，不能注册到真实渠道表。`authoritative: true` 是适配器对证据来源的声明，协调器无法自行证明它；实际适配器必须验证来源和订单与提交的关联，不能凭空赋值。

订单创建时间采用保守比较；平台时钟差异或秒级精度可能使真实订单进入未知，未来适配时须处理并测试，不能简单扩大时间窗口认领旧订单。页面导航、标签身份、错误分类与异步旧页面动作的隔离也必须在真实适配器中验收。

## 集成范围与限制

后台已接入 `PURCHASE_STATUS / START / TICK / STOP / RESUME / RECONCILE`。购买命令仅接受扩展 dashboard 来源；普通官方网页不能发消息自选适配器并启动。`chrome.storage.local` 限可信扩展上下文访问，内容脚本仍可通过已有受校验的采集消息上报公开信息。依据：[Chrome storage 官方文档](https://developer.chrome.com/docs/extensions/reference/api/storage)。

当前没有实际派发器、真实页面元素识别、官方订单读取、观演人选择逻辑或持续监测调度。一个后台实例的串行执行不等于跨设备、跨浏览器或服务器侧的“恰好一次”。后台消息参数、测试或网页按钮文案都不能当作真实锁票证据。

下一步应基于可正常加载的实际购买渠道实现适配器和脱敏页面契约测试，再在用户本机观察模式验收。App限定项目不能通过把电脑网页按钮强制点开来接通。无需将用户目标限定为某一场演出，但需分别验证所支持的页面类型。现阶段不能承诺任何场次的成功率。
