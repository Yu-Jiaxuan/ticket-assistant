# 票务助手：先把购票流程跑明白

想做这个项目，是因为抢票时要在很短的时间里选场次、选票价、确认信息。首选没票了，还得赶紧去看备选，很容易手忙脚乱。

最终希望做到：**提前登录自己的账号，设置好想买的场次和票档，程序按顺序尝试，成功后提醒本人付款。**

先说清楚：**现在还不能直接在大麦自动下单或锁票。**这是一个能运行的早期原型：可以在本地演示完整的判断流程，也有一个观察大麦网页文字变化的小扩展。真实大麦的选票、提交订单部分还没接好，不建议拿它直接参加正式抢票。

## 现在已经做了什么？

| 你想做的事 | 目前能做到哪一步 |
|---|---|
| 先试首选，没票再试备选 | 本地演示已实现，可以自己设置顺序 |
| 限制张数和总价 | 判断逻辑已实现，超预算或张数不对会停下 |
| 遇到验证码、掉登录、排队 | 演示中会暂停，提示人工处理；还不能识别真实大麦的所有情况 |
| 提交后一直转圈怎么办 | 记下这次提交，先停下来查结果，不马上再下一单 |
| 刷新后会不会重复购买 | 演示保留提交记录，未确认的订单会阻止继续尝试 |
| 页面出现“立即购买”等文字时提醒 | 扩展代码已实现；还没在登录后的大麦页面实际验收 |
| 自动查询大麦余票、选票并下单 | **还没实现** |
| 付款 | 正式使用时由本人在官方页面完成；演示里的付款是假的 |

## 先体验一下：首选没票，自动看备选

下载代码并解压，电脑需要装好 Python 3。在项目文件夹里打开终端，输入：

```sh
python -m http.server 8765 --bind 127.0.0.1
```

然后用 Chrome 或 Edge 打开 [本地演示页面](http://127.0.0.1:8765/demo/)。

页面默认准备了三个模拟选择：

1. 周六晚场，680 元。
2. 周六晚场，480 元。
3. 周日晚场，680 元。

选择“首选售罄 → 备选成功”，点击“启动模拟购票”。你会看到它跳过首选，尝试第二个票档，生成模拟订单后停下来。点“模拟付款”也不会扣钱——整个演示没有连接大麦。

还可以切换不同情况，看看程序怎么处理：提交时突然没票、要求验证码、网络超时、登录失效、排队、页面改变、已有待付款订单，以及结算价格超出预算。

每次换场景前，先核对并清除演示记录。通过上面的本地网址打开，不要直接双击 HTML；多标签防重复运行需要浏览器提供的 Web Locks。演示在开售后最多等待两分钟。

## 网页扩展怎么用？

扩展适合这种情况：你已经打开大麦官方网页，想让它在页面出现某段文字时提醒一下。

1. 打开 `chrome://extensions` 或 `edge://extensions`，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择项目里的 `extension` 文件夹。
3. 打开大麦官方 HTTPS 网页，自己登录账号。
4. 点击扩展图标，填写要观察的文字，比如“立即购买”，再点开始。
5. 网页右下角会显示观察状态，可以在那里停止。

**它只观察当前页面，不会自动刷新，也不会查服务器余票。**如果网页本身没有更新，它就不知道新票有没有放出来。出现“立即购买”也不代表你的目标票档真的有票，更不代表锁票成功。

刷新或跳转页面后要重新启动，关闭页面后观察结束。声音可能被浏览器限制，所以主要看页面提示。扩展不读取 Cookie、不保存账号密码、不操作支付。

## 为什么提交失败后不能一直重试？

因为“没看到成功”不一定是“没买到”。例如服务器已经创建订单，但页面卡住了，这时候继续尝试备选，可能会重复下单。

所以目前的处理是：**明确售罄、明确没有形成订单，才继续看备选；结果不明，就暂停核对。**遇到验证码或排队，也会交给本人处理，不做自动代答或绕过。

## 哪些地方检查过了？

- 11 项核心自动测试全部通过，包括备选顺序、预算限制、异常暂停和重复提交保护。
- 页面及扩展脚本通过语法检查。
- 浏览器里的完整演示、扩展安装以及真实大麦操作**还没完成验收**：当时环境缺少浏览器，下载又超时了。

测试通过只说明所测判断逻辑符合预期，不代表已经能在大麦抢到票。详细结果在 [测试记录](docs/TEST-REPORT.md)。

## 适合谁用？

目前适合想体验购票流程自动化、研究异常处理，或者愿意一起完善浏览器扩展的人。网页文字观察功能可以作为简单辅助，但也需要先在自己的浏览器测试。

如果你要的是“下载后直接参加正式抢票，只等付款”，这个版本还达不到。它也不是大麦官方工具，不能保证抢到票。

## 后面准备补什么？

下一步先选一个具体演出，核实它能不能在网页上买票，以及实际的选票、结算、验证流程，再决定怎样接入。适配完成前，不会凭猜测去点购买按钮。

遇到问题可以提交 Issue，写上程序版本、浏览器版本、选择的模拟场景，以及卡在哪一步。请不要上传密码、Cookie、验证码、完整身份证号或带个人信息的订单截图。

更详细的实现思路和维护办法在 [设计与维护说明](docs/DESIGN.md)，更新内容在 [更新记录](CHANGELOG.md)。

## 想自己改代码

Node.js 20 或以上即可运行核心测试，不需要安装依赖：

```sh
npm test
```

需要跑浏览器测试时，先启动上面的本地服务器，再执行：

```sh
npm install --no-save playwright
npx playwright install chromium
node tests/browser.cjs
```

| 文件夹 / 文件 | 放的是什么 |
|---|---|
| `extension/engine.js` | 决定什么时候等待、尝试、切备选或停止 |
| `extension/` 其余文件 | Chrome / Edge 页面观察扩展 |
| `demo/` | 本地模拟购票页面 |
| `tests/` | 自动测试 |
| `docs/` | 设计思路、维护办法和测试记录 |
